# GroundTruth dashboard

The three views that make the argument: the same day read twice, the day as a
timeline, and the spans the classifier refused to guess at.

```bash
npm install
npm run dev     # http://localhost:5173
```

`npm run dev` serves all three views immediately. No server is required — see
**Data** below.

| script | what it does |
|---|---|
| `npm run dev` | dev server, proxying the API to `GROUNDTRUTH_SERVER` |
| `npm run build` | typecheck and build to `dist/` |
| `npm run preview` | serve the build |
| `npm run typecheck` | types only |
| `npm run fixture` | regenerate `src/data/day.json` from `scripts/make-fixture.mjs` |

## The three views

**Contrast** (`#/contrast`) is the headline. Both decompositions come from
`GET /summary`: `naive_by_process` is what a conventional tracker would have
reported, `groups` is what GroundTruth reports. They are drawn as two bars of
equal width, one above the other, so equal length means equal time and the eye
compares the two cuts with no axis to reconcile. The application bar is divided
and labelled exactly like the activity bar but carries no colour, because an
application name carries no information about what was done — the absence is the
point. On load the activity bar resolves from that same neutral into the
category palette, left to right.

The contract gives no link between a process and the categories inside it —
`naive_by_process` and `groups` are independent decompositions of one window, and
`Session` has no `process` field. So the view never claims "chrome.exe *became*
research and doomscrolling". It claims only that the same eight hours answer
differently depending on the question, which is the honest reading and the
stronger one.

**Timeline** (`#/timeline`) renders `GET /sessions` over an hour ruler, each
session sized by duration and coloured by category. Hover or focus a block for
its label, confidence and the evidence the classifier cited. Unanswered spans sit
on their own track beneath, so the holes they leave in the session lane are
visible rather than papered over. Every session is also in a table below, which
is the same data without needing a pointer.

**Uncertain** (`#/uncertain`) is `GET /uncertain` as a short queue, each span
answerable in one click via `POST /uncertain/{id}/resolve`. The chosen category is
the answer and the label defaults to it, so answering never requires composing a
phrase first; a more specific label can be typed under "Something else". Answering
moves that time out of `uncertain` and into the chosen category across all three
views, which is what the server does when it re-segments.

## Data

The client calls the live server and falls back to a bundled sample day when
nothing answers, recording which one it got and stating it in the header — `live`
or `sample day`. A dashboard arguing about whether you can trust a tracker should
not let fixture numbers read as a live day.

- **Live.** `npm run dev` proxies `/summary`, `/sessions`, `/uncertain` and
  `/events` to `GROUNDTRUTH_SERVER` (default `http://127.0.0.1:8000`), so the
  browser sees one origin and the server keeps its loopback-only binding. For a
  build, point `VITE_GROUNDTRUTH_SERVER` at an absolute base, or deploy
  same-origin.
- **Fixture.** `src/data/day.json` is one authored 8-hour day, generated by
  `scripts/make-fixture.mjs`. The day is written once as a run of contiguous
  segments and every published figure — category totals, process totals, shares —
  is computed from it, so the fixture cannot drift out of internal consistency.
  The generator refuses to write a file whose groups do not sum to the total,
  whose sessions and unanswered spans leave a gap, or whose confidences sit below
  the agent's accept threshold.

  Its totals land on the worked example in `docs/API.md` and the README —
  8h tracked, deep work 6000s, doomscrolling 9060s, chrome.exe 15120s — so the
  fixture demonstrates the documented numbers rather than a second, contradictory
  set.

  To use the server's fixture instead, copy `server/fixtures/day.json` over
  `src/data/day.json`. The loader accepts `sessions`/`uncertain` as either the
  bare arrays or the endpoints' `{ sessions }` / `{ spans }` envelopes, so no code
  change is needed.

No figure in the UI is written by hand. Every number renders from fixture or API
data, and the one constant the UI states on its own — the confidence threshold a
label has to clear — mirrors `Confidence.ACCEPT` in `agent/groundtruth/types.py`.

## Design

**Colour lives in `src/styles/tokens.css` and nowhere else.** Components reference
roles (`--cat-research`, `--ink-muted`, `--surface-1`); none carries a literal
colour. That is what keeps a category the same colour in all three views without
any of them knowing about the others.

Dark and light are both selected rather than derived — the dark steps are the same
eight hues re-stepped for the dark surface, because an automatic inversion lands
outside the usable lightness band. `prefers-color-scheme` drives the default; the
header control forces one for a demo and `auto` returns to following the OS.

The category palette is eight hues assigned by meaning — cool for intentional
attention, warm for consumed attention, violet and rose for the personal
categories — plus three deliberate neutrals. `admin` and `idle` are grey because
they are overhead and absence, and `uncertain` is hatched because it is a question
rather than an activity. `doomscrolling` is not alarm-red: the system reports what
happened and does not grade it, which is a stated non-goal in `ARCHITECTURE.md`.

The palette was validated in both modes with a colourblind-separation checker
(OKLab ΔE ×100, Machado-Oliveira-Fernandes simulation at severity 1.0):

| | adjacent pairs | all pairs |
|---|---|---|
| light | CVD 14.0 / normal 18.0 | CVD 8.3 / normal 15.3 |
| dark | CVD 13.8 / normal 16.0 | CVD 6.9 / normal 15.3 |

Bars and stacked segments are an adjacent-pair form, which both modes clear
outright. Timeline adjacency is data-driven rather than legend-driven, so the
all-pairs figures matter too: normal vision clears the ≥15 floor in both modes,
and dark all-pairs CVD sits in the 6–8 band that is legal only with secondary
encoding. Every category mark in this UI therefore carries a text label, a legend
entry and a 2px surface gap — identity is never carried by colour alone.

Nine categories would need a ninth hue, and there isn't one: an unknown category
resolves to `--cat-other` rather than to a generated colour.

## Layout and motion

Built for 1280px and screen recording; it degrades to a phone without breaking,
but desktop is the priority. The contrast reveal runs about a second with no
bounce and no overshoot, and `prefers-reduced-motion` renders the final state
immediately rather than a fast version of the animation.

## Dependencies

React and React DOM. Everything else — the stacked bars, the timeline, the
tooltip, the hash routing, the theme control — is hand-rolled, and all styling is
plain CSS with custom properties.
